# True or Not UI 고도화 디자인 방향

## 범위

기획서 v2를 기준으로 프론트엔드 화면과 명시적인 데모 상호작용을 구현합니다. 검색·LLM·URL 수집 API 연결은 이번 범위에 포함하지 않습니다.

## 디자인 결정

| 항목 | 방향 |
|---|---|
| 제품 인상 | 근거를 읽고 비교하는 차분한 프리미엄 리서치 워크스페이스 |
| 화면 구조 | 내비게이션, 간결한 헤더, 입력, 원문·주장·근거 비교 |
| 색상 | 기존 다크 배경 유지, 시안 주요 액션, 보라 보조 강조, 노란 원문 선택 |
| 글자 | 한국어 시스템 글꼴 fallback, 읽기 쉬운 본문과 제한적인 영문 보조 라벨 |
| 카드 | 대비가 충분한 다크 글래스, 절제된 테두리·반사광 |
| 아이콘 | 동일한 선 굵기의 로컬 SVG, 운영체제 이모지 미사용 |
| 모션 | Motion의 선택·진입 전환, reduced-motion 적용 |
| 배경 | Paper Design 쉐이더의 점진적 로딩, 정적 배경 fallback |
| 모바일 | 원문·결과·출처 간 선택 유지, 터치 가능한 컨트롤과 가로 넘침 방지 |
| 신뢰 표시 | 전역 데모 안내, 허구의 예시 자료 명시, 실제 연결 상태 오인 방지 |

## 패키지 활용 원칙

설치된 패키지를 무조건 모두 렌더링하지 않습니다. Motion과 쉐이더는 실제 시각 효과에 활용하되, Three.js 계열은 이번 화면에 필요하지 않으면 로드하지 않습니다. Liquid Glass 사용 시 입력 폼을 복제하지 않으며 기능 안정성·가독성을 우선합니다. 효과는 핵심 입력과 근거 읽기를 방해하지 않아야 합니다.

## 디자인 조사 근거

`ui-ux-pro-max`의 `research workspace dark glass` 검색은 포트폴리오·학술 서체 중심으로 제품과 맞지 않아 채택하지 않았습니다. 한 번 좁혀 검색한 `SaaS dashboard dark` 결과의 Glassmorphism, 얇은 테두리, 절제된 blur·깊이 원칙은 활용합니다. 범용 랜딩 페이지 구조와 밝은 팔레트는 사용자 지정 다크 워크스페이스에 맞지 않아 적용하지 않습니다.

Next.js 스택 지침에서 인터랙티브 영역의 클라이언트 경계 분리와 무거운 기능 분할을 참고합니다. 로컬 작업 상태는 라우트 로딩과 다르므로 별도의 React 상태로 유지합니다.

## 검증 항목

- 원문·주장·근거의 선택 동기화
- 직접 입력에 실제 검증 판정·허위 출처를 생성하지 않음
- 실행 중 대상 스냅샷 유지, 취소 이후 지연 완료 무시
- URL 미연결 안내와 본문 입력 대안
- 예시 상세·가이드 대화상자의 닫기·키보드 동작
- 고유 ID, 입력 label, 명확한 포커스, 화면 상태 안내
- 데스크톱·모바일·가로 방향의 overflow 확인
- 타입 검사·프로덕션 빌드·상태 테스트·브라우저 콘솔 확인

실행 결과는 별도 검증 기록에 기록하며, 이 문서는 결과 통과를 주장하지 않습니다.
