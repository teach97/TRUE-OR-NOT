# True or Not 작업현황

기준일: 2026-10-03. 역할: 완료·남은 작업·미결정 사항의 단일 목록. 기존 PRD·구현현황·단계표·v4의 L/FR/R/C/S 항목을 T 작업과 D 결정으로 통합했다. 기준 문서는 [기획서](기획서.md), [아키텍처](아키텍처.md), [배포](배포.md), [QA](qa/검증기준.md)다.

구현 완료는 실공급자·원격 성공을 뜻하지 않는다. 이번 문서 정리로 아래 미완료 코드나 정책을 자동으로 적용하지 않았다. 검증 증거는 [날짜별 실행기록](qa/실행기록/)에만 관리한다.

## 먼저 볼 작업

1. 정책과 독립적으로 계산 오류(T13), CI·테스트 누락(T18), 공개 안내 불일치(T26)를 정리한다.
2. 확정한 JEV 유형 분류·동의·공통 호출 한도·개요 상태 구분을 적용하고 공개 범위·한도 수치·점수 정책을 결정한다.
3. PostgreSQL 대화 저장·불러오기를 추가하고 소유권·보관·삭제 정책을 확정한다. 코드와 계약을 보완하고 Docker·Render를 연결한다.
4. 기존 1회 재탐색의 전후 비교·네 가지 핵심 지표, 대화 저장 시험, 입력별 원격 회귀, 시연을 완료한다.

## 역할과 산출물

A~D는 기존 4인 팀의 분담 권장안이며 실명 배정·일정은 D15에서 결정한다.

| 역할 | 주된 범위 |
|---|---|
| A · 프론트·프록시 | 동의·접근·한도·점수·상태 표시, 화면·프론트 배포 |
| B · 검증 엔진 | JEV 유형·인용·비교·계산·합성 상태, 복구 품질 |
| C · 검색·그래프·배포 | runtime·workflow·provider·source 연결, 백엔드·Docker·Render |
| D · 계약·QA·문서 | 계약 변경 검토, CI·사례·지표·검증 기록·발표 |

공유 계약과 runtime 변경은 관련 담당이 함께 검토한다. 유료 QA는 D14의 예산·담당 범위로 실행한다. 발표에는 기존 구현·이번 개선·개인 기여·코드 기준·실측 결과·미확인을 구분하고, 고정된 Python 호출을 자율적 Function Calling으로 설명하지 않는다. 평가 기준은 [QA 검증기준](qa/검증기준.md)에 둔다.
