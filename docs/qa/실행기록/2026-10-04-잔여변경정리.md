## 재현과 회귀 검증

- 처리 전 기존 Python 실패 3개와 Node 실패 5개를 재현했습니다. MAX·Finnhub의 두 실패는 구정책 시험, YouTube 실패는 실제 영상정보 누락이었습니다. Node의 첫 시험이 동시 10건을 가정하여 실패한 뒤 후속 4개 시험이 연쇄 실패했습니다.
- 변경된 MAX 개요·MAX 요약·Finnhub 설정·시장 계약의 회귀 시험 4개를 기존 커밋의 분리된 임시 복사본에서 실패시키고 현행 코드에서 통과시켰습니다. 요약 시험의 잘못된 설정 필드명은 수정한 뒤 HIGH→MAX 불일치를 실제로 재현했으며, 잘못된 fixture 실패를 회귀 증거로 세지 않았습니다.
- YouTube·동시 실행은 실제 실패→복원→통과 순서로 확인했습니다. 실패 원인을 숨기기 위해 시험을 비활성화하지 않았습니다.
- 미사용 토스 전용 시험 5개를 제거하고 시장 시험 3개를 5개로 확장했으며, 요약·계약 시험 각 1개를 추가했습니다. 시험 총수 감소는 제거된 기능의 전용 시험 때문입니다.

## 제외 범위와 인계

- DB·Render 서비스·접속 비밀값·사용자의 기존 서버는 변경하지 않았습니다. 실제 LLM·검색·YouTube·Finnhub 호출과 유료 리소스 변경은 수행하지 않았습니다.
- 미결정 공통 한도, 원격 시연·공개 배포, 개인정보 안내의 기존 부채는 관련 T 작업에서 관리합니다. 이번 정리를 전체 공개 준비 완료로 표시하지 않습니다.
- 독립 최종 검토는 Critical·Important·Minor 지적 없이 제한된 정리 범위의 반영 가능으로 판정했습니다. 검토자는 전체 시험을 재실행하지 않았으며 실행자가 위 결과를 직접 확인했습니다.
- 검토에서 제외한 실공급자 권한·종목 지원·속도·비용·원격 배포는 T15·D9에 남깁니다. 공통·사용자별·다중 인스턴스 비용 한도는 D11에 남깁니다. 동의·JEV·개요 상태·개인정보 안내·CI 및 기본 명령의 요약 시험 누락도 기존 작업 범위를 유지합니다.
- 검토자가 제외한 Graphify·생성 파일·ZIP 원본 해시는 실행자가 따로 대조했습니다. SQL parser 및 기존 노드 경고는 미해결로 기록하며 ZIP 백업은 원본 해시와 일치합니다. 별도 DB 작업은 필요하지 않아 수행하지 않았습니다.
- 전체 staged diff의 실제 환경 설정 비밀값 대조 0건, 임시 비교 복사본 삭제 및 3000/3017/8010/8017 리스너 없음 확인. 기존 사용자 서버가 실행 중이지 않아 재시작하지 않았습니다.
- 사용자 기존 main 반영 지시에 따라 일반 커밋·푸시하고 원격 SHA 일치 여부를 최종 인계에서 확인합니다. force push는 사용하지 않습니다.
