## 지원·생략 경계

| 입력 | 계산 참고값 |
|---|---|
| 가격이 2,000원에서 2,500원으로 올랐다 | 25% |
| 매출이 100억 원에서 130억원으로 늘었다 | 30%. 단위 내부의 일반 공백·탭만 정규화 |
| 수량 10개→8개 | -20% |
| 매출 100억원, 직원 20명 / 가격 100원, 배송비 130원 | 생략. 다른 항목을 연결하지 않음 |
| 매출 100억원에서 순이익 130억원으로 바뀌었다 | 생략. 두 값 사이의 항목명이 다름 |
| 가격 10만원에서 100000원으로 바뀌었다 | 생략. 단위 환산은 지원하지 않음 |
| 가격은 100원에서 130원까지다 / 100원부터 130원까지다 | 생략. 변화가 아닌 범위 |
| 단위 없는 숫자·연도·비율/퍼센트포인트·음수·분수·지수·잘못된 쉼표 표기 | 생략 |

지원 단위는 원·달러·명·개·건과 천·만·억·조 접두 단위다. 같은 단위가 적힌 `에서 … 으로/로`, `→`, `->` 표기에서만 계산한다. 단위 내부는 일반 공백·탭만 지원하며 NBSP·줄바꿈으로 단위가 분리된 표기는 생략한다. 전체 자연어의 의미나 단위를 추론하는 파서가 아니며 불명확한 계산은 생략한다. 최대 3개 계산의 기존 상한과 `expression`·`percent` 계약은 유지한다.

실제 표시 형태인 `2,000원→2,500원`도 별도 로컬 호출에서 `[{"expression":"2000→2500","percent":25.0}]`를 반환했다. 같은 호출에서 매출/직원 수와 가격 범위는 모두 빈 계산 목록을 반환했다.

리뷰에서 숫자 앞의 한 글자만 검사하면 `100~200원`·`1/2원`의 뒷값과 공백으로 분리된 `- 100원`을 양수로 받아들이는 문제를 재현했다. 시작 위치 앞의 공백과 수치 연산 기호를 검사해 생략하고, 새 값 뒤의 범위·분수도 제외했다. 화살표의 단위 종료 경계를 `에서 … 으로/로` 조사 검사와 분리하여 `2000원→2500원 상승했다` 같은 설명문은 정상 계산한다. 각 원인은 재현 테스트로 보존한다.

다른 지표를 인접 값으로 연결하던 기존 테스트 기대는 새 안전 경계에 맞게 생략으로 변경하였다. 계산 상한은 실제로 독립된 네 개의 변화에서 앞의 세 개만 반환하는지 검증하였다. 검증기 모델 요청을 모의 전송 계층에서 포착해 지원하는 계산만 `computed`에 포함되고 잘못된 비교는 비어 있는 것을 확인하였다.
