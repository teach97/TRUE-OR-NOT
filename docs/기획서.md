# True or Not 기획서

기준일: 2026-10-03. 역할: 제품 목적·범위·확정 정책. 구현 사실은 [아키텍처](아키텍처.md), 미결정 정책과 작업 상태는 [작업현황](작업현황.md)을 따른다. 기존 v4의 제품 내용을 통합한 현행 기획서다.

## 제품 목적

True or Not은 기사·댓글·온라인 주장에 의문을 가진 사용자가 개별 주장과 근거를 추적·비교하는 생활형 검증 도구다. 입력에서 확인할 주장을 추출하고 실제 자료의 인용·수치·날짜·비교 조건을 연결해 확인된 내용과 불확실한 내용을 함께 보여준다.

온라인 텍스트에는 사실·의견·예측·과장·오래된 정보가 섞여 있다. 같은 발표를 재인용한 여러 기사나 기간·지역이 다른 통계가 독립적인 확인 또는 직접적인 반박으로 오해될 수 있다. 사용자가 결론의 한계와 연결된 원문을 이해하는 것이 목표다.

## 대상과 활용 상황

| 상황 | 확인할 내용 | 제공할 정보 |
|---|---|---|
| 생활 물가 기사 | 어떤 상품이 언제 얼마나 올랐는가 | 기간·대상·단위가 맞는 근거 |
| 정책 관련 댓글 | 확정 정책인가, 검토안인가 | 발표·시행 시점과 정책 상태 |
| 문화 행사 정보 | 올해 일정인가, 과거 기사인가 | 행사 연도·지역·공식 공지 |
| 과장된 문장 | 사실 부분과 해석은 무엇인가 | 사실 요소와 의견, 빠진 맥락 |

## 제공하는 흐름

1. 텍스트·링크와 확인 요청을 입력한다. 이미지 경로도 구현되어 있으나 공식 제공 범위는 D4에서 결정한다.
2. 내용 요약 요청은 검증과 구분해 요약을 제공한다. 짧은 대화는 의도 분류를 거쳐 검증 또는 답변으로 분기한다.
3. 최대 3개 주장을 자동으로 추출·검증한다. 검증 전 후보 선택 단계는 현재 없다.
4. 결과에서 주장별 판정·인용·출처·조건·경고와 AI 개요를 읽고 원문을 확인한다.
5. 취소·재요청과 JSON 내보내기를 제공한다. 데모는 합성 예시로 명시한다.

외부 전송 동의는 사용자 확인과 실제 호출을 연결해야 한다. 현재 화면의 동의 자동 입력과 intent의 검사 누락은 미완료 작업이며, 명시적 동의 절차가 구현되었다고 설명하지 않는다.

## 제품 원칙

- 검색 결과 부재를 거짓의 증거로 사용하지 않는다. 직접 근거가 부족하면 결론을 유보한다.
- 실제 수집 원문과 대조한 인용을 근거로 제공한다. AI 설명·검색 요약을 원문 인용으로 표시하지 않는다.
- 기간·지역·단위·대상·모집단이 다른 자료는 먼저 비교 조건을 확인한다.
- 출처 수와 독립적인 근거 수를 구분한다. 공식 출처나 금융 매체라는 이유만으로 확인 판정·가산점을 주지 않는다.
- 사실·의견·예측을 구분한다. 미래 결과를 현재 확정하거나 의견을 거짓으로 판정하지 않는다.
- 입력·수집 문서의 지시문은 비신뢰 데이터로 취급한다. 접근 차단·로그인·유료벽을 우회하지 않는다.
- 검증 시각·범위·한계와 데모 여부를 표시한다. 측정하지 않은 서비스 정확도 수치를 홍보하지 않는다.
- 처리 생략·처리 실패와 근거 부족의 의미를 구분한다. 현재 개요 상태 표시의 불일치는 T14에서 관리한다.

## 판정의 의미

| 판정 | 의미 |
|---|---|
| 대체로 확인됨 | 핵심 사실·조건과 직접 관련된 근거가 일치 |
| 일부만 확인됨 | 복합 주장의 일부 또는 일부 조건만 확인 |
| 맥락이 생략됨 | 조건·기간·범위 생략으로 의미가 달라짐 |
| 출처 간 내용이 다름 | 같은 조건의 지지·반박 근거가 충돌 |
| 근거 부족 | 직접 근거 미확보 또는 검색 범위 내 판단 불가 |
| 검증 대상 아님 | 의견·가치 판단·현재 확정할 수 없는 예측 등 |
| 반박하는 근거 확인 | 같은 조건의 직접 근거가 핵심 주장을 반박 |

판정은 원문 근거와 함께 읽는다. 점수는 측정된 서비스 정확도가 아니다. 주장별 점수·종합 평균의 표시 정책은 D1이 미결정이며, 현재 표시 방식은 아키텍처에 기록한다.

|---|---|

| 배포 대상 | Render로 결정. 실제 배포·공개 대상·요금제·호출 한도는 작업현황과 배포 문서에서 관리 |

| 후속 후보 | 주장 선택·편집·재검증, 원자료 계보, KOSIS/KRX, 대화 공유·정정 알림 |
| 현재 범위 밖 | 전체 크롤링·SNS 감시, 작성자 평가, 개인정보·얼굴 분석, 자동 신고·삭제·차단, 개인별 의학·법률·투자 판단, 영상·음성 자체 분석, 브라우저 확장, 다중 에이전트 플랫폼 |

로그인·보관함·DB 영속 저장은 현재 제공하지 않는다. PostgreSQL 기반 대화 저장·불러오기는 이번 추가 기획 범위이며, 구현·배포 완료와 구분한다. 금융 기능을 편입하더라도 매매 권고를 제공하지 않는 기존 범위를 유지한다.

## 이번 확정 추가 기획

2026-10-03 사용자 요청으로 아래 범위를 편입합니다. PostgreSQL 장기기억은 **사용자 대화 저장·불러오기용**이며 복구 전략 통계 저장용이 아닙니다. 요구사항 확정은 코드 구현·DB 구축·실공급자 시험·배포 완료를 의미하지 않습니다. 진행 상태와 미결정 운영값은 [작업현황](작업현황.md)에서 관리합니다.

### JEV 유형 분류·동의·공통 호출 한도

| 요구사항 | 적용 정책·완료 기준 |
|---|---|
| JEV 유형 분류 | 메인 검증의 JEV 옵션과 빠른 경로 모두 추출·유형 분류를 적용합니다. 입력 전체를 사실 주장 1개로 고정하지 않으며 사실·의견·예측·불명확한 주장을 구분합니다. 혼합 입력은 사실 요소만 검증하고 의견·예측을 현재 확정된 사실로 점수 판정하지 않습니다. 분류 불가 시 판단을 유보하고 판정 엔진·실제 모델·전환 여부를 표시합니다. |
| 명시적 전송 동의 | intent·검증·JEV·요약 등 모든 외부 호출 경로에서 첫 전송 전에 사용자 확인을 받고 서버에서도 검사합니다. 동의 값을 자동 입력하지 않습니다. 동의 대상·목적·수신 서비스를 안내하고, 동의가 없거나 철회된 요청은 외부 호출 전에 차단합니다. 재탐색도 유효한 동의 범위 안에서만 실행합니다. |
| 공통 호출 한도 | 메인·보조 API에 공통 접근·동시 실행·사용자별 횟수·비용 정책을 적용합니다. 모델 폴백과 내부 재탐색의 추가 사용량도 같은 예산에 포함하며 경로 변경 시 초기화하지 않습니다. 여러 인스턴스에서도 한도 우회를 막고 초과 요청을 외부 호출 전에 차단합니다. 수치·집계 기간·공통 제한 구현 방식은 D11에서 결정합니다. |

공유 시크릿은 프록시와 백엔드 간 보호 수단이며 이용자 인증·대화 소유권 검사·호출 한도를 대신하지 않습니다. 전송 동의의 유효 기간·재확인 방식은 D12에서 결정합니다.

### 근거 부족·생성 생략·생성 실패 구분

주장 판정과 AI 개요 생성 상태를 별도로 관리합니다. 백엔드 계약·프론트 검증·화면·대화 저장에 같은 의미를 적용하며 기술 장애를 사실 판정의 근거로 사용하지 않습니다.

| 상태 | 의미·안내 |
|---|---|
| 근거 부족 | 검증은 수행했으나 직접 근거를 확보하지 못했거나 비교 조건이 부족합니다. 사실·거짓을 단정하지 않고 확인 범위와 부족한 조건을 설명합니다. 적절한 판단 유보는 정상 결과로 취급할 수 있습니다. |
| 생성 생략 | 개요 생성 조건이나 대상이 없어 생성 호출을 의도적으로 하지 않았습니다. 생략 이유를 표시하고 호출하지 않은 모델이나 생성 완료된 개요가 있는 것처럼 표시하지 않습니다. |
| 생성 실패 | 생성은 시도했으나 공급자 오류·시간 초과·응답 형식 또는 인용 검증 오류로 유효한 개요를 만들지 못했습니다. 처리 실패와 재시도 가능 여부를 안내합니다. 이미 유효하게 검증된 주장·근거는 보존하고 생성 실패를 근거 부족으로 바꾸지 않습니다. |

유효한 개요가 생성된 경우에는 생성 완료로 표시합니다. 근거 부족은 주장 판정, 생략·실패·완료는 생성 상태이므로 함께 나타날 수 있습니다. 필드명·기존 계약 이행 방식은 T14에서 구현하며 저장한 대화에도 동일하게 적용합니다.

### 기존 1회 재탐색 활용

- 기존 `review_recovery`와 검증→검색 조건부 복귀를 활용합니다. 별도 LLM 진단·계획 호출이나 다중 에이전트 구조는 추가하지 않습니다.
- 사실 또는 불명확한 주장에 근거가 부족하고 원문 접근 실패·인용 검증 거절이 함께 확인될 때에만 요청 내부에서 최대 1회 재탐색합니다.
- 검색어를 수정하고 실패·거절된 출처 및 리다이렉트 변형을 제외하되 정상 출처는 후보로 유지합니다. 제출 원문·추출 주장 스냅샷을 보존하고 새 인용의 원문 일치·참조 무결성을 다시 검사합니다.
- 일반 근거 부족·의견·예측·입력 오류·취소에는 재탐색을 강제하지 않습니다. 공급자 장애 전체를 이 경로로 복구한다고 설명하지 않습니다.
- 전체 제한 시간·동의·공통 호출 예산을 초기화하지 않습니다. 메인 스트림의 기존 240초 전체 제한 안에서 남은 시간·예산이 부족하면 재탐색을 생략하거나 중단하고 이유를 안내합니다. 별도 복구 시간 상한은 운영 설정으로 정하되 미측정 응답 속도를 보장하지 않습니다.
- 1회 후에도 직접 근거가 부족하면 판단을 유보하고 종료합니다. 내부 복구·모델 폴백·사용자 재요청·QA 실행기의 HTTP 재요청을 분리해 기록합니다.

### 복구 전후 시험과 네 가지 핵심 지표

고정된 10~15개 사례로 기존 실행과 개선 실행을 비교합니다. 사례 ID·기대 행동·코드 기준·모델·추론 설정·반복 수·예산을 실행 전에 고정하고 모의 오류 주입과 실제 공급자 시험을 구분합니다. 사례·반복 수·유료 실행 예산·담당은 D14에서 확정합니다.

| 핵심 지표 | 계산·평가 기준 |
|---|---|
| 태스크 완료율 | 사전 기대 행동·결과를 충족한 사례 수 / 전체 사례 수. 정당한 의견 제외·판단 유보는 성공으로 인정할 수 있으며 처리 실패와 구분합니다. |
| 도구·복구 행동 선택 정확도 | 사전 정의한 허용 행동과 일치한 선택 수 / 평가 가능한 선택 수. 재탐색과 무재탐색 선택도 평가하며 고정된 도구 순서를 자율 선택 정확도로 보고하지 않습니다. 평가 불가 사례는 별도 표시합니다. |
| 응답 일관성 | 동일 입력·조건의 반복 묶음에서 판정·처리 상태가 일치한 묶음 수 / 전체 반복 묶음 수. 문구 일치가 아니라 판정과 처리 의미를 비교합니다. |
| 평균 내부 복구 횟수 | 요청 내부 품질 복구 횟수 합 / 전체 요청 수. 요청당 0~1회이며 폴백·사용자·HTTP 재요청은 제외합니다. |

시간·비용·인용 정합성은 별도 보조 지표입니다. 전체 및 재탐색 소요 시간, 외부 호출 수, 토큰·검색 사용량, 원문 인용·비교 조건을 함께 관측합니다. 근거가 하나 생겼다는 내부 표시나 HTTP 성공만으로 태스크 완료를 인정하지 않습니다.

정상 실행·접근 실패·인용 거절·복구 성공·복구 소진·일반 근거 부족·의견·예측·공급자 오류·취소·시간 초과를 포함합니다. 동의 거부·한도 초과는 외부 호출 0회를 확인합니다. 날짜별 QA 실행기록에 전후 값·통과·실패·미실행과 원본 증거를 남기며 측정하지 않은 수치를 채우지 않습니다.

### PostgreSQL 기반 대화 저장·불러오기

#### 목적과 최소 범위

- 저장에 동의한 대화의 사용자 메시지와 화면에 제공한 assistant 답변을 PostgreSQL에 저장합니다. 새로고침·백엔드 재시작·재배포 후에도 같은 소유자가 대화 목록과 메시지를 불러와 이어갈 수 있어야 합니다.
- 첫 범위는 대화 목록·선택·복원·이어쓰기·삭제입니다. 복구 전략 학습, 벡터 DB·임베딩, 전체 과거 대화 검색, 자동 기억 요약, 타인과의 공유는 포함하지 않습니다.
- 복원한 검증 결과는 당시 검증 시각과 출처를 표시합니다. 과거 답변을 현재 사실의 증거나 최신 검증 결과로 재사용하지 않으며 후속 검증은 기존 검색·원문 확인 절차를 거칩니다.

#### 최소 데이터 구조

| 테이블 | 주요 저장 항목 |
|---|---|
| `conversations` | 대화 ID, 서버에서 확인한 소유자 식별값, 대화 제목, 생성·갱신 시각 |
| `messages` | 메시지 ID, 대화 ID, 순서, 역할, 메시지 본문, 완료·실패·취소 등 처리 상태, 생성 시각, 중복 저장 방지용 요청 식별값 |

대시보드 복원이 필요한 assistant 메시지에는 사용자에게 제공한 주장·판정·인용·출처 URL·검증 시각의 최소 결과 스냅샷을 함께 저장합니다. 전체 수집 원문·첨부 바이너리·공급자 원시 응답·원시 사고 과정·서비스 API 키와 토큰은 저장하지 않습니다. 메시지는 대화에 종속시키고 순서 및 동일 요청의 중복 저장을 DB 제약으로 방지합니다.

#### 처리·접근·삭제 정책

1. 외부 서비스 전송 동의와 서버 대화 보관 동의를 구분합니다. 저장 목적·항목·보관·삭제 방법을 안내하고 보관에 동의한 대화만 영속 저장합니다. 저장하지 않는 대화도 기존 사용 범위 안에서 이용할 수 있어야 합니다.
2. 조회·이어쓰기·삭제 때마다 서버에서 소유권을 검사합니다. 클라이언트가 보낸 사용자 ID나 대화 ID만 신뢰하지 않습니다. 로그인 기반 또는 검증 가능한 익명 세션 중 식별 방식을 D17에서 정하며 다른 사용자에게 대화가 노출되는 상태로 공개하지 않습니다.
3. 사용자 메시지와 유효하게 완료된 답변을 순서대로 저장합니다. 스트림의 임시 미리보기를 완료 답변으로 저장하지 않으며 실패·취소 시 상태를 구분합니다. 저장 재시도는 동일 요청을 중복 생성하거나 LLM 호출을 다시 실행하지 않습니다.
4. 후속 요청의 문맥은 선택한 대화의 최근 메시지만 기존 입력·컨텍스트 한도 안에서 사용합니다. 전체 이력을 매번 모델에 보내지 않으며 과거 메시지의 지시문도 비신뢰 데이터로 취급합니다.
5. DB 장애·저장 시간 초과와 검증·생성 실패를 구분합니다. 유효한 답변은 화면에 유지하고 저장되지 않았음을 안내합니다. DB 읽기·쓰기 제한 시간은 D13에서 정하며 새 LLM 요약 호출을 추가하지 않습니다.
6. 대화 삭제 시 소유권을 확인한 뒤 해당 대화와 메시지를 함께 삭제하고 더 이상 조회·문맥으로 사용할 수 없게 합니다. 보관 기간·자동 삭제·백업 보존 및 삭제 반영 기준은 D17에서 확정하고 공개 전 안내합니다.
7. PostgreSQL 접속 정보는 백엔드 서버 환경 설정으로만 관리하고 프론트엔드·저장소·로그에 노출하지 않습니다. DB 호스팅·접속 보호·운영 비용은 D13에서 정하며 이번 문서 반영으로 유료 DB를 생성하거나 배포하지 않습니다.

#### 대화 저장 수용 시험

| 시험 | 통과 기준 |
|---|---|
| 저장·복원·이어쓰기 | 새로고침·서버 재시작 후 메시지 순서·역할·처리 상태·검증 시각이 복원되고 선택한 대화에 후속 메시지가 이어집니다. |
| 소유권·동의 | 다른 사용자의 대화 ID로 조회·쓰기·삭제가 불가능하며 보관 동의가 없는 대화는 DB에 저장하지 않습니다. |
| 중복·실패·취소 | 동일 요청 재전송 시 메시지가 중복되지 않고 생성 실패·취소·저장 실패가 완료 답변으로 표시되지 않습니다. 저장 재시도로 외부 생성 호출이 추가되지 않습니다. |
| 삭제·보관 | 삭제한 대화 및 메시지가 목록·직접 조회·후속 문맥에서 제외됩니다. 확정한 보관·백업 정책을 실제 동작과 대조합니다. |
| 속도·비용 | 저장 전후의 전체 소요 시간·DB 처리 시간·외부 호출 수를 비교합니다. D14에서 시험 전 확정한 허용 추가 지연·통과 기준과 D13의 DB 제한 시간 준수 여부를 검사합니다. 추가 LLM 호출은 없어야 하며 기준이 미정이면 관측값만 기록하고 속도 합격으로 보고하지 않습니다. |

이 기능은 T33~T34의 계획이며 현재 로그인·대화 DB·저장 API가 구현되었다고 표시하지 않습니다.

## 화면과 안내

한국어 다크 화면에서 입력·원문·주장·근거를 연결하고 모바일에서도 선택을 유지한다. 원문 강조와 주장 선택, 인라인 출처, 날짜·비교 조건·접근 상태를 읽기 쉽게 표시한다. 키보드·포커스·reduced-motion과 가로 넘침은 QA 기준으로 확인한다.

소개 문구: “그 주장, 근거까지 보이나요? True or Not은 주장과 출처를 연결해 확인된 내용과 불확실한 내용을 함께 비교하는 검증 도구입니다.”

데모 안내: “데모 모드입니다. 표시된 주장·출처·결과는 화면 흐름을 설명하기 위한 예시이며 실제 검증 결과가 아닙니다.”

결과 안내: “이 결과는 표시된 검증 시각에 접근한 자료를 기준으로 작성되었습니다. 검색 범위와 자료 접근에 한계가 있으며, 새로운 자료에 따라 달라질 수 있습니다. 중요한 판단 전에는 연결된 원문을 직접 확인해 주세요.”
