# True or Not Render 배포

기준일: 2026-10-03. DB 호스팅 결정 추가: 2026-10-04. 역할: 배포 설정·절차·완료 확인. 플랫폼은 Render로 확정했으며 서비스 생성·이미지 빌드·원격 검증은 아직 수행하지 않았다. 현재 공백과 담당은 [작업현황](작업현황.md), 코드 동작은 [아키텍처](아키텍처.md)를 따른다.

## 구성과 환경 설정

[render.yaml](../render.yaml)을 기준으로 Next.js와 FastAPI Docker 서비스를 두 개 구성한다.

| 서비스 | 설정 | 값·역할 |
|---|---|---|
| 백엔드 | Docker 컨텍스트 `backend`, [Dockerfile](../backend/Dockerfile) | `${PORT:-8010}`으로 바인딩, `/health` 생존 확인 |
| 백엔드 | `OPENAI_API_KEY`, `GEMINI_API_KEY` | 사용할 공급자 키. 적어도 하나 필요, 없는 공급자는 건너뜀 |
| 백엔드 | `TAVILY_API_KEY`, `TYPESAFE_API_KEY`, `YOUTUBE_API_KEY`, `FINNHUB_API_KEY` | 선택 기능의 키. 실제 권한·지원 범위 별도 확인 |
| 백엔드 | `BACKEND_SHARED_SECRET` | 프론트 공유 시크릿과 같은 값, `/health` 외 요청 헤더 보호 |
| 프론트 | 루트 Docker 컨텍스트와 [Dockerfile](../Dockerfile) | `${PORT:-3000}`으로 바인딩 |
| 프론트 | `FACTLENS_BACKEND_URL` | 실제 백엔드 HTTPS URL. Blueprint의 예시 주소와 대조 |
| 프론트 | `FACTLENS_ALLOW_REMOTE_BACKEND=1` | 원격 HTTPS 백엔드 허용 |
| 프론트 | `FACTLENS_PUBLIC_DEPLOY=1` | 기본 로컬 요청 정책을 공개 모드로 전환 |
| 프론트 | `FACTLENS_BACKEND_SECRET` | 백엔드와 동일, 서버 전용. `NEXT_PUBLIC_*`로 노출하지 않음 |

키 값은 Render 환경 설정에 주입한다. [.dockerignore](../.dockerignore)와 [백엔드 제외 규칙](../backend/.dockerignore)은 `.env*`·가상환경·캐시를 제외한다. 예제 파일은 키 이름만 안내하며 실제 값을 넣어 커밋하지 않는다.

## 대화 저장 DB · Render PostgreSQL

2026-10-04 대화 저장 DB 호스팅을 Render PostgreSQL로 확정했다. 연결 흐름은 `Next.js → FastAPI → Render PostgreSQL`이다. 현재 `render.yaml`에는 대화 DB 선언·연결이 없으며 DB 드라이버·테이블·저장 API도 미구현이다. 다음 절차는 구현·배포 계획이며 완료 기록이 아니다.

1. D13에서 워크스페이스·요금제·리전을 확정하고 기존 DB와 무료 DB 사용 여부를 확인한다. 백엔드와 같은 워크스페이스·리전에 생성하며 유료 생성·전환은 별도 승인 없이 실행하지 않는다.
2. Render 백엔드는 내부 연결 주소를 서버 전용 `DATABASE_URL`로 사용한다. 로컬 개발은 외부 연결 주소와 TLS를 사용하고 외부 접근 허용 IP를 제한한다. 접속 URL의 비밀번호를 화면·로그·문서·Git에 기록하지 않는다.
3. T33·T34에서 DB 연결·대화/메시지 테이블·저장/조회/삭제 API·서버 소유권 검사·보관 동의를 구현한다. 연결 제한 시간과 실패 안내를 적용하고 DB 저장 실패로 LLM을 재호출하지 않는다.
4. 새로고침·서버 재시작 후 복원, 타인 접근·동의 없는 저장 차단, 삭제·중복 방지·DB 장애 및 저장 전후 지연을 검증한다. [기획서의 대화 저장 수용 시험](기획서.md#대화-저장-수용-시험)을 따른다.

단기 개발·시연에는 무료 DB를 권장하지만 요금제 확정과 생성 완료로 표시하지 않는다. 공식 문서 확인일 2026-10-04 기준 무료 DB는 워크스페이스당 1개, 1GB, 생성 후 30일 만료이며 백업을 제공하지 않는다. 만료 뒤 14일 유예 기간이 지나면 데이터가 삭제되므로 지속 보관을 보장하지 않는다. 시연 종료 전 필요한 데이터를 안전하게 내보내거나 별도 승인 후 유료 전환을 결정한다. [무료 DB 제한](https://render.com/docs/free), [DB 생성·연결](https://render.com/docs/postgresql-creating-connecting).

## 배포 전 결정·보완

- D10~D13의 공개 대상·한도·동의·요금제·인스턴스를 확정하고 T10·T11을 반영한다. 공개 게이트와 서버 공유 시크릿만으로 사용자 제한이 생기지 않는다.
- 선택 기능·시연 입력을 정해 필요한 키와 권한만 확인한다. 미확인 기능은 공개·시연 범위에서 구분한다.
- 현재 `/health`의 리비전은 Git 조회에 의존한다. Docker에는 Git 저장소·커밋값 전달이 없어 T16의 배포 식별값 주입을 보완해야 한다.
- 무료 인스턴스 휴면·재시작과 장시간 스트림은 실제 선택한 요금제에서 확인한다. 현재 영속 작업 큐·재시작 후 복구는 없다.

## 적용 순서

1. 배포할 커밋을 고정하고 두 Docker 컨텍스트에서 이미지를 빌드한다. 최종 이미지에 비밀 파일이 없는지 확인한다.
2. Render에서 Blueprint로 두 서비스를 만들고 환경변수·공유 시크릿을 설정한다. 실제 백엔드 URL을 프론트에 반영한다.
3. 백엔드 시작·배포 식별값을 확인한 뒤 프론트를 연결한다. 생존 응답과 모델 연결 성공은 별도로 검사한다.
4. 아래 원격 완료 기준을 실행하고 날짜·코드·환경·결과를 [QA 실행기록](qa/실행기록/)에 남긴다.

## 원격 완료 기준

| 확인 항목 | 통과 조건 |
|---|---|
| 이미지·환경 | 두 서비스 시작, 키·비밀 파일 미포함, 실제 백엔드 URL과 공유 값 일치 |
| 서버 경계 | 잘못된 공유 헤더 차단, 올바른 프록시 연결 |
| 이용자 경계 | 허용·비허용·초과 요청을 외부 호출 전에 구분 |
| 동의 | 동의 전 intent 포함 외부 전송 없음, 동의 후 허용 경로 정상 |
| 검증·요약 | 선택한 모델·입력에서 정상 결과, 판단 유보, 처리 실패를 구분 |
| 스트림·복구 | 단계·출처·최종 결과 전달, 최대 1회 재탐색·소진 종료 |
| 시간·취소·재요청 | 전체 제한 유지, 취소 종료, 재요청 가능, 늦은 결과 혼동 없음 |
| 선택 기능 | 발표용 JEV·자막·시장 데이터만 실제 확인, 실패 시 기본 검증 유지 |
| 배포 기준 | 결과 기록과 배포 커밋·설정 일치, 정상·유보·실패 시연 리허설 |

이 기준을 통과하기 전 상태는 배포 준비·검증 대기다. 문서와 설정의 존재를 실제 서비스 배포 성공으로 표시하지 않는다.
