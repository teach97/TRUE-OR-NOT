# Render PostgreSQL 대화 저장 설계안

작성일: 2026-10-04. 상태: 사용자의 실제 DB 생성·대화 저장 구현 재요청으로 설계 승인, 구현 계획 검토 대기. 기준 정책은 [기획서](../../기획서.md#postgresql-기반-대화-저장불러오기), 진행 상태는 [작업현황](../../작업현황.md)의 T33·T34를 따른다. 설계 문서의 존재를 DB 생성·제품 구현 완료로 표시하지 않는다.

## 확인한 요청과 구현 경계

- 사용자는 Render의 **My Workspace**에 실제 DB 생성과 대화 저장 구현을 요청했다. 무료 DB로 시작하며 유료 생성·전환은 실행하지 않는다.
- 소유권 방식은 사용자가 선택한 **익명 세션**이다. 같은 브라우저에서 목록·복원·이어쓰기·삭제를 제공한다. 쿠키 삭제·만료 후에는 이전 대화에 접근할 수 없으며 로그인·기기 간 동기화는 포함하지 않는다.
- 저장 동의는 외부 전송 동의와 별개이다. 동의하지 않은 대화도 기존 기능을 사용할 수 있다. 기존 사용자 서버·미커밋 코드·다른 Render 프로젝트는 보존한다.
- 확인한 My Workspace에는 PostgreSQL DB가 없다. 기존 `chat-service-backend`는 다른 저장소의 서비스이므로 환경변수·배포·리소스를 변경하지 않는다. True or Not용 Render 웹서비스도 아직 없다.

## 선택한 접근

| 접근 | 특성 | 결정 |
|---|---|---|
| 서버가 검증하는 익명 쿠키 + PostgreSQL | 기존 채팅에 저장·복원을 연결하며 별도 로그인 서비스가 필요하지 않는다. 브라우저 쿠키가 접근 수단이다. | 사용자 선택 |
| 로그인 + PostgreSQL | 여러 기기에서 복원이 가능하지만 로그인·계정 복구·계정 삭제 범위가 추가된다. | 이번 범위 제외 |

흐름은 `브라우저 → Next.js 동일 출처 API → FastAPI → Render PostgreSQL`이다. DB 자격증명·세션 서명 키는 FastAPI 환경 설정에만 둔다. Next.js는 DB에 접속하지 않는다.

## Render 리소스와 연결

- 새 인스턴스 이름은 `true-or-not-conversations`, 요금제는 `free`, 저장 공간은 1GB로 제안한다. 한국 사용자와 향후 서비스 연결을 고려해 Singapore 리전·PostgreSQL 18을 사용한다. 이후 True or Not 백엔드도 같은 워크스페이스·리전에 배치한다.
- DB 생성 요청의 결과가 불명확하면 목록·이름·생성 상태를 먼저 확인한다. 같은 이름의 리소스를 재사용하며 중복 생성하거나 유료 플랜으로 우회하지 않는다.
- 생성 직후 사용 가능 상태·리전·요금제·만료 시각을 확인한다. 로컬 연결은 외부 URL과 TLS, Render 백엔드는 내부 URL을 사용한다. 외부 허용 IP는 필요한 개발 IP로 제한한다.
- 실제 URL은 무시되는 백엔드 환경 파일이나 서버 비밀 설정에만 넣는다. `.env.example`에는 변수명·빈 값만 기록한다. Git·화면·로그·실행 기록에는 비밀번호·세션 키·쿠키 토큰을 남기지 않는다.
- 무료 DB는 생성 후 30일에 접근이 만료되고 백업이 없다. 14일 유예 뒤 삭제될 수 있으므로 영구 보관을 약속하지 않는다. 이번 단계에서는 자동 업그레이드·별도 백업 서비스·만료 대응 자동 작업을 만들지 않는다. [공식 무료 제한](https://render.com/docs/free), [생성·연결](https://render.com/docs/postgresql-creating-connecting).
- True or Not 웹서비스 생성·공개 배포는 별도 T15 범위이다. 이번 검증은 기존 로컬 앱과 실제 Render DB를 연결하며 다른 프로젝트 서비스를 대신 사용하지 않는다.

## 익명 소유권과 요청 보호

1. 저장을 켤 때 FastAPI가 무작위 소유자 식별값과 발급·만료 시각을 포함한 HMAC-SHA256 서명 토큰을 생성한다. 세션 유효 기간 제안은 30일이며 DB의 생성 시각 기준 만료와는 별개이다.
2. Next.js는 토큰을 `HttpOnly`, `SameSite=Lax`, `Path=/` 쿠키로 설정한다. HTTPS 운영 환경에서는 `Secure`를 필수로 적용하고 로컬 loopback HTTP 개발만 예외로 한다. 토큰을 브라우저 JavaScript·localStorage·JSON 본문에 반환하지 않는다.
3. Next.js는 쿠키의 토큰만 백엔드 전용 헤더로 전달한다. FastAPI는 전용 `CONVERSATION_SESSION_SECRET`으로 서명·형식·발급/만료 시각을 검증한다. 클라이언트가 보낸 소유자 ID나 임의 헤더를 신뢰하지 않는다.
4. 모든 대화 SQL은 검증된 소유자 조건을 포함한다. 다른 소유자의 ID로 조회·추가·삭제하면 존재 여부를 노출하지 않는 404를 반환한다. 쿠키가 없거나 변조·만료되면 401을 반환하며 기존 소유자를 임의 복구하지 않는다.
5. 저장·세션 발급·삭제 등 변경 요청은 동일 출처 Origin/Fetch Metadata 검사를 적용한다. 본문 크기와 Content-Type을 검사하고 응답은 `Cache-Control: no-store`로 제공한다. 기존 프록시↔백엔드 공유 시크릿 보호도 유지한다.
6. 서명 키가 없으면 저장 API만 비활성화한다. 프로세스 재시작마다 새 키를 만들거나 개발 기본 키를 제공하지 않는다. 키 교체 시 기존 쿠키가 무효화된다는 점을 운영 안내에 기록한다.

## DB와 저장 계약

별도 로그인·세션 테이블 없이 기획서의 두 테이블을 사용한다. Python 저장 계약·TypeScript 공유 계약·클라이언트 검증을 함께 추가한다.

| 테이블 | 열·제약 |
|---|---|
| `conversations` | UUID `id`, 서버가 확인한 `owner_id`, 생성 요청 UUID `create_request_id`, 최대 80자 제목, `created_at`, `updated_at`. `(owner_id, create_request_id)`는 UNIQUE이며 소유자·갱신 시각 인덱스로 목록을 조회한다. |
| `messages` | UUID `id`, 대화 외래 키, 대화 내 `sequence`, `role`, `content`, `status`, 요청 UUID `request_id`, 선택적 정제 `snapshot` JSONB, `created_at`. 외래 키는 대화 삭제 시 CASCADE, 순서와 `(conversation_id, request_id, role)`은 UNIQUE이다. |

- 사용자 메시지는 기존 12,000자 입력 범위를 보존한다. assistant 본문은 최대 60,000자, 단일 저장 요청은 512KB로 제한한다. 초과는 저장 오류이며 이미 생성된 답변을 실패로 바꾸지 않는다.
- `role`은 `user`·`assistant`, `status`는 `completed`·`failed`·`cancelled`로 제한한다. 일시적인 로딩·사고 미리보기·환영 문구·데모 메시지·이미지 바이너리는 저장하지 않는다.
- 저장 전용 스냅샷은 제출 텍스트·확인 요청·주장·판정·인용·출처의 URL/제목/발행인·검증 시각·최종 개요만 허용한다. 전체 원문, 목차 본문, 시장 데이터, YouTube API 메타데이터·댓글, 원시 공급자 응답·진행 상태·비밀값은 제외한다. 복원 시 빠진 선택 필드는 안전한 빈 값으로 보완한다.
- 클라이언트가 전송한 스냅샷은 별도 허용 필드 계약으로 검증·정제한다. 저장된 대화는 해당 소유자의 과거 기록이지 외부에 제시할 검증 인증서가 아니다. 복원한 결과에는 원래 검증 시각과 과거 결과 안내를 표시한다.
- 메시지 추가는 대화 행 잠금과 트랜잭션으로 다음 순서를 배정한다. 같은 요청 UUID·역할을 재전송하면 기존 결과를 반환한다. 재시도 내용이 바뀌면 409로 거부한다. 생성·삭제와 경합해도 중복·순서 충돌이나 삭제된 대화의 부활이 없어야 한다.
- 비동기 PostgreSQL 드라이버와 최대 4개 연결의 애플리케이션 풀을 사용한다. 단일 API의 전체 DB 작업에 3초 제한을 적용하고 연결/풀 대기·각 SQL도 남은 제한 시간을 넘기지 않도록 한다. DB 장애를 제공자/검증 장애와 다른 오류로 반환한다.
- 마이그레이션은 프로젝트 테이블만 생성하는 반복 가능한 명령으로 제공한다. 기존 데이터베이스 삭제·DROP·다른 프로젝트의 테이블 변경은 실행하지 않는다.

## API와 화면

동일 경로를 Next.js에서 프록시하고 FastAPI에서 구현한다. 조회는 페이지 크기를 제한한다. 저장 요청의 `storageConsent=true`를 서버에서 확인하며 화면 체크박스는 기본 꺼짐이다.

| 경로 | 동작 |
|---|---|
| `GET /api/conversations/status` | 비밀값 없이 DB 설정·세션 사용 가능 여부를 반환한다. 검증 기능의 상태와 구분한다. |
| `POST /api/conversations/session` | 사용자가 저장 동의 후 익명 세션을 발급한다. 유효한 기존 세션이면 같은 소유자를 유지한다. |
| `GET /api/conversations` | 현재 소유자의 대화 목록을 갱신 시각 내림차순으로 최대 30개 조회한다. 다음 페이지는 커서로 조회한다. |
| `POST /api/conversations` | 저장 동의 확인 후 대화를 생성한다. 생성 요청 UUID로 중복 대화를 방지한다. |
| `GET /api/conversations/{id}` | 소유자 확인 후 메시지를 순서대로 최대 100개 조회한다. 이전 메시지는 커서로 조회한다. |
| `POST /api/conversations/{id}/messages` | 동의·소유권·계약 검사 후 사용자/완료/실패/취소 메시지를 추가한다. |
| `DELETE /api/conversations/{id}` | 소유자 확인 후 대화와 메시지를 함께 삭제한다. |

- 사이드바에 ‘새 대화’, 저장된 대화 목록·선택·삭제를 추가하고 기존 블랙앤화이트 UI를 유지한다. 모바일에서도 목록을 열 수 있어야 한다. 삭제는 대상 제목을 보여 주고 확인 후 실행한다.
- 저장 동의는 ‘이 브라우저에서 대화 저장’으로 표시하며 목적·저장 항목·쿠키 삭제 시 접근 불가·무료 DB 만료·삭제 방법을 안내한다. 전송 동의를 저장 동의로 재사용하지 않는다.
- 동의 후 신규 사용자 메시지를 저장하고 정상 완료된 assistant 답변·정제 결과를 저장한다. 실패·취소는 완료 답변과 구분한다. 저장 실패 시 화면 내용과 요청 UUID를 유지하여 저장만 재시도할 수 있게 한다. 저장 재시도로 LLM을 다시 실행하지 않는다.
- 저장을 끄면 새 메시지는 저장하지 않는다. 이미 저장한 대화를 자동 삭제하지 않으며 삭제 버튼을 별도로 제공한다. 대화 선택이나 페이지 새로고침으로 저장 동의를 자동 체크하지 않는다.
- 대화 변경·새 대화·삭제 중 진행 중인 생성이 있으면 취소한다. 대화별 실행 식별값으로 늦게 도착한 결과가 다른 대화에 표시·저장되는 것을 막는다. 중복 클릭·연속 제출·저장 중 삭제도 검증한다.
- 복원한 메시지와 마지막 유효 검증 결과를 기존 채팅/대시보드 상태에 연결한다. 후속 문맥은 기존 `gateContext`의 최근 사용자 3개·이전 원문/주장 제한을 유지한다. 전체 이력을 모델에 보내거나 추가 요약 LLM을 호출하지 않는다.
- 서버에 무기한 보관을 약속하지 않는다. 이번 무료 시연안의 보관 제안은 사용자 삭제 또는 DB 만료까지이며, 쿠키 만료는 데이터 삭제와 같지 않다. 지속 운영·자동 삭제·백업 정책 변경은 별도 결정한다.

## 검증과 완료 기준

1. 실패하는 계약·세션·저장 테스트를 먼저 작성한다. 서명 변조/만료/키 누락, 타인 대화 접근, 무동의 쓰기, 중복/경합/삭제, 본문 상한·정제 제외 필드를 검증한다.
2. Next.js 프록시의 쿠키 속성·동일 출처·토큰 비노출·응답 제한·오류 매핑과 클라이언트 복원/저장 실패/취소 경합을 테스트한다. 전체 기존 테스트·타입 검사·빌드를 실행하며 기존 실패는 별도로 기록한다.
3. 실제 Render DB에서 합성 메시지 생성→조회→중복 재전송→다른 소유자 차단→재연결 후 복원→삭제를 확인한다. 시험 데이터는 요청 범위 안에서만 만들고 종료 후 제거한다. 이 시험에 실제 LLM·유료 검색 호출은 필요하지 않다.
4. 실제 브라우저에서 저장 켜기·새로고침 복원·이어쓰기·삭제·동의 끄기·DB 장애 안내를 확인한다. 과거 출처 링크와 검증 시각이 유지되고 저장 재시도의 외부 호출 수가 0이어야 한다.
5. 요청 전체 시간과 DB 처리 시간을 관측한다. 각 DB 처리 제한 3초 준수와 추가 LLM 호출 없음을 확인한다. 측정 전 평균 추가 지연이나 운영 성능을 보장하지 않는다.
6. 기존 미커밋 10개 항목을 보존하고 이번 기능 변경만 검증·커밋·일반 push한다. 코드 작업 후 Graphify를 갱신한다. 임시 시험 프로세스·브라우저를 종료하고 기존 사용자 서버는 보존한다.

## 검토 후 다음 단계
